# Contact Page — "Book a Call" Modal

## Goal
Add a "Book a call" button to `src/pages/contact.astro` that opens an accessible modal containing a booking form: name, email, topic, notes, plus a **custom calendar** (month grid) and **time-slot picker**. Submitting shows an in-modal confirmation (no mailto, no backend).

## Files

### 1. New: `src/islands/BookCall.tsx` (React island)
The site already has React 19 wired up and one island pattern to follow (`ContactForm.tsx`), so the modal is a second React island containing both the trigger button and the modal (keeps open/close state in one place).

**Trigger** — a button styled like the existing primary CTAs (`bg-brand-text text-white rounded-[10px] px-6 py-[15px]`, hover lift with `--ease-out-expo`, 180ms), with a small calendar icon, labeled "Book a call".

**Modal** — rendered when open:
- Fixed overlay: dimmed backdrop (`bg-ink/40` + slight blur) + centered panel (`.card-paper` surface, `rounded-[var(--radius-lg)]`, max-w ~560px, scrollable on small screens).
- Accessibility: `role="dialog"` + `aria-modal="true"` + `aria-labelledby`; focus moves to the dialog on open and returns to the trigger on close; Escape closes; backdrop click closes; a visible close (×) button; body scroll locked via the existing `lockScroll()` from `src/lib/scroll.ts`; entrance uses a 180ms fade/rise animation that is disabled under `prefers-reduced-motion`.
- Header: mono eyebrow "Book a call" + short title ("Pick a 30-minute slot") + close button.

**Form details** (reusing the `Field` label/hint/error pattern from `ContactForm.tsx` — duplicated locally, not refactored out, to keep the change minimal):
- Name (required), Email (required, same regex), Topic (required `<select>` reusing the `SERVICES` list), Notes (optional textarea, "What should we prepare?").
- Same input styling as ContactForm: `rounded-[10px] border-line-strong bg-white px-4 py-3.5 focus:ring-2 focus:ring-brand/35`, error color `#c8384f` with `aria-invalid`/`aria-describedby`, inline validation on blur/submit with focus moved to first invalid field.

**Custom calendar** (state: viewed month, selected date, selected time):
- Header row: `‹` / month-year label (e.g. "September 2026") / `›`; prev/next navigate months, with prev disabled on the current month and next capped ~3 months out.
- Weekday header (Mon–Sun) + 6-row month grid; day buttons for the current month only, **past days disabled** (today selectable).
- Selected day highlighted `bg-brand-text text-white`; today gets a ring/dot; disabled days are dimmed with `aria-disabled`.
- **Time slots**: grouped list under the calendar — Morning (09:00, 10:30, 11:30) / Afternoon (14:00, 15:30, 17:00) — rendered as pill toggle buttons in the same select style; if the selected day is today, slots earlier than now are disabled. Selecting a date resets the chosen time.
- Validation: date and time required ("Pick a day" / "Pick a time").

**Confirmation state** (on valid submit, `role="status"`): check icon in a circle (mirrors ContactForm's sent card), "You're booked in." headline, summary line with formatted date + time (e.g. "Thursday, 10 September · 14:00") and the chosen topic, note "We'll confirm by email at {email}", and a "Done" button that closes the modal and resets the form.

## Constraints honored
- Button/inputs `rounded-[10px]`, brand-text `#0060e6` for interactive blue (never `#006bff` with white text), 180ms `--ease-out-expo` transitions, steel-tinted shadows, 44px touch targets on coarse pointers, reduced-motion support, focus-visible outlines.
- TypeScript strict; no new dependencies.
- No backend involvement; confirmation-only per your choice. The confirmation copy will be honest ("we'll confirm by email") without claiming an invite was sent.
