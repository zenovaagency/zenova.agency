# Animated blue + purple gradient background for the bottom-of-page contact card

The "contact card" is `src/components/chrome/Cta.astro` (the "Got an idea? Let's talk." banner above the footer on 10 pages; `contact.astro` intentionally has no CTA — it *is* the contact page — so it stays unchanged).

**Approach:** Extend the existing `.card-live` CSS animation system in `src/styles/cards.css` (drifting light lobes, already used by the Services cards) with a violet light lobe, then opt the CTA card in and shift its base ramp toward indigo/violet. Pure CSS — no JS, no WebGL, reduced-motion safe.

## Changes

### 1. `src/styles/cards.css` — extend the `.card-live` section (lines 154–279)
- Update the now-stale rationale comment (lines 155–158) that says the footer CTA must *not* animate — it now opts in deliberately.
- Add a `.card-live > .card-glow-violet` layer: `position: absolute; inset: -35%; z-index: 0; pointer-events: none`, a violet radial lobe (`#6D28D9` violet at ~0.28 alpha) plus a `::before` indigo lobe (`#4338CA` at ~0.24 alpha) so two purple depths compose over the blue ambient `.card-glow`.
- Add one new `@keyframes card-drift-c` — transform-only (`translate3d` + `scale`), resting at its 0% keyframe per the house convention documented in the file (so the global reduced-motion freeze lands on today's static look).
- Add the animation rule for the violet lobe inside the existing `@media (prefers-reduced-motion: no-preference)` block, using the same `--i` desync formula (`calc(31s + var(--i, 0) * 6s)` etc.).
- Extend the contrast commentary with measured numbers, matching the file's house style: violet-700 `#6D28D9` L ≈ 0.10 and indigo-600 `#4338CA` L ≈ 0.08 — both below the 0.183 white-text ceiling even composited over the lightest ramp pixel (`#0060E6` + blush bloom, L 0.153); dark lobes only raise contrast (same argument the file already makes for its dark lobe).

### 2. `src/components/chrome/Cta.astro`
- Add `card-live` to the card's class list and render two child spans as first children: `<span class="card-glow" aria-hidden="true"></span>` (existing blue ambient + hover sweep) and `<span class="card-glow-violet" aria-hidden="true"></span>`.
- Extend the inline style to `--angle: 118deg; --i: 4; --stop-a: #1e1a5e; --stop-b: #4338ca` — `--i: 4` desyncs from Services' 0–3 (unique durations/delays), and the two per-instance stops shift the base ramp to **deep indigo → violet-blue → brand blue** (keeping the blue `--stop-c` default), so the card clearly reads blue + purple. All new stops measure L ≤ 0.12, safely under the documented 0.183 ceiling for the white text.

### 3. `src/components/home/Services.astro`
- Touch up the comment (lines 31–34) claiming `.card-live` stays off the other `.card-bleed` callers — the footer CTA now also opts in.

## Constraints honored
- White text contrast: worst-pixel luminance stays ≤ 0.183 (4.5:1), using the same arithmetic already documented in `cards.css`.
- Purple comes from true indigo/violet stops, not blush+blue mixing (the codebase's comments treat blue+pink→lavender as a failure mode).
- All new animation gated behind `prefers-reduced-motion: no-preference`; keyframes rest at 0%.
- No JavaScript, no changes to `Base.astro` — every page rendering `<Cta />` picks the animation up automatically.
